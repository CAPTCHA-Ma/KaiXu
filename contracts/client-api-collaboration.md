# 客户端与后端联调约定清单

此文是后续确认清单，不是已经实现的 API。现有服务端尚不可运行；正式路径、字段与错误结构由双方评审后，以服务端导出的 OpenAPI 和脱敏样本落实。

| 要确认的内容 | 客户端对应位置 | 需要达成的约定 |
| --- | --- | --- |
| 请求 / 响应字段 | data/dto、data/mapper | ID类型、必填、空值、日期精度、状态枚举、分页 |
| 认证与账号范围 | core/session、core/network | 凭据携带、失效、退出、缓存账号隔离 |
| 版本与冲突 | Repository、ViewModel、UiState | 提交版本、过期拒绝、最新记录、保留草稿和再次提交 |
| 幂等 | UseCase输入、远程数据源 | 本次操作标识、重复提交返回同一结果、响应丢失后查询 |
| 权限失效 | 数据层错误映射与共享页面状态 | 服务端每次鉴权，客户端立即使无权访问的内容失效 |
| 时间 | DTO与mapper、纯时间规则 | Asia/Shanghai、日期和时刻分开、半开区间 |
| 离线 | Repository、本地缓存、UiState | 仅个人缓存只读，更新时间，无写队列与重连自动提交 |
| 跨对象操作 | UseCase、单次命令接口 | 完成任务与未来时段处理、候选确认、删除脱链由后端原子保证 |

新接口至少准备成功、输入无效、未认证、无权限、版本冲突和重复请求样本，适用哪些场景由具体用例决定。接口错误转换为客户端可识别结果，页面再决定反馈；不要把后端堆栈直接显示给用户。

客户端不直连 PostgreSQL，也不将后端 ORM 模型复制成 UiState。现有 `rules-fixtures/task-title.json` 是教学规则样本，当前两侧尚未以同一文件运行契约测试。
