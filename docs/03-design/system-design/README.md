# KaiXu 软件系统设计总览

> 版本：v1.0（2026-11-02）  
> 需求基线：SRS 2026-10-23 + 《KaiXu 用例分解》2026-11-01  
> 设计范围：Windows 桌面端、Android 端、服务端、数据库、接口、UI/UX、安全  
> 状态：设计基线。接口与数据库在首次联调评审后冻结为 v1.1。

## 1 设计目标

KaiXu 把分散在课程平台、群聊和文件中的学习信息，整理成可执行的任务、固定事件和工作时段；个人计划与项目协作共享同一套任务结构，同时严格隔离私人执行数据。系统设计围绕五个目标展开：

1. **先本地、后同步**：桌面端在未登录或断网时仍能完成完整个人工作流；联网后可靠补传，不丢失、不重复、不越权。
2. **共享目标、私密执行**：项目成员共享任务、事件、资料与进度；工作时段、本人剩余估时、番茄钟明细永远只属于本人。
3. **两端一致、能力有别**：桌面承担完整管理，Android 只承担在线查看、快速录入、状态更新、简单改期和番茄钟。
4. **人确认、机建议**：外部来源、规则排程和 AI 只产生候选或草案，正式写入必须经用户确认。
5. **四人团队可交付**：优先模块化单体、清晰事务边界和可测试的规则，不引入不必要的微服务与运维复杂度。

## 2 关键设计决策

| 编号 | 决策 | 结论 | 理由 |
| --- | --- | --- | --- |
| ADR-01 | 系统架构 | 模块化单体（Modular Monolith） | 四人团队、强事务需求多、共享权限与完成操作需原子提交；单体一个部署单元即可满足课程规模，后续可按模块拆分 |
| ADR-02 | 桌面数据策略 | Local-first：SQLite + SQLCipher，本地事务 + Outbox 同步 | 用例分解要求桌面未登录/断网可完整读写；SRS 的只读缓存规则已被修订 |
| ADR-03 | Android 数据策略 | Online-only：必须登录且联网，不建业务缓存与离线写队列 | 用例分解明确 Android 不以缓存继续业务；减少双端一致性与隐私风险 |
| ADR-04 | 接口风格 | REST + JSON + OpenAPI 3.1 | 资源边界清晰、客户端代码生成成熟、调试成本低；当前查询复杂度不需要 GraphQL |
| ADR-05 | 并发控制 | 每实体 `version` + 客户端 `operationId` 幂等 | 支持离线编辑、重复提交、响应丢失和多人并发；比时间戳可靠 |
| ADR-06 | 共享数据权威 | 服务端权威；桌面共享内容默认是最近同步快照 | 成员移除、权限变更和共享进度必须以服务端为准 |
| ADR-07 | AI 调用 | 桌面直连用户配置的 OpenAI 兼容服务，Key 仅存本机凭据库 | 避免服务端保存用户第三方 Key；AI 结果只作建议，不进入业务同步 |
| ADR-08 | 时间规则 | 全系统固定 `Asia/Shanghai`；日期与时刻分开存储 | 满足 BR13；避免设备时区改变截止含义 |
| ADR-09 | 文件存储 | S3 兼容对象存储 + 短时预签名 URL | 数据库只存元数据；附件版本、权限和校验和可审计 |
| ADR-10 | 实时性 | v1 不做 WebSocket 推送，使用刷新/同步拉取 | NFR-P03 只要求刷新后 5 秒内可见；降低实现与测试成本 |

## 3 范围与非目标

### 3.1 本期范围

- 课程/项目工作区、任务、任务阶段、固定事件、工作时段、资料与附件版本。
- 桌面本地库、账号分库、离线读写、待同步队列、冲突处理。
- Android 在线今日/近期视图、快速录入、状态更新、本人时段的简单改期、番茄钟。
- 项目邀请、成员与所有者角色、共享任务/事件/资料、共享范围确认。
- 外部来源候选、人工粘贴、字段变更确认、重复识别。
- 可选 AI：配置、群聊提取任务建议、资料关联建议、阶段分解建议、估时建议。
- 规则排程草案（不依赖 AI）、锁定项、容量不足提示。
- 账号、会话、权限、审计、备份与恢复。

### 3.2 非目标

- 不做微服务、服务网格、Kubernetes 多集群；本期单区域部署。
- 不做 Android 离线业务、Android 完整任务编辑、Android 成员管理、Android AI。
- 不做逐项共享开关；共享以项目整体确认为准。
- 不做多人实时协同光标/实时推送；冲突通过版本比较解决。
- 不做跨用户共享个人课程；共享项目关联的课程对无权限成员只显示“私人课程”。
- 不把 AI 作为核心业务前提；无 Key、断网、超时都必须保留人工路径。
- 不承诺生产级 SLA；性能指标按 SRS 7.1 的验收环境度量。

## 4 需求差异与设计取舍

《KaiXu 用例分解》是对 SRS 的修订，以下差异直接影响架构，设计以修订版为准：

| 主题 | SRS 原规则 | 用例分解修订 | 设计落实 |
| --- | --- | --- | --- |
| 桌面离线 | FR-X05：离线仅只读缓存，不支持离线编辑与写队列 | 桌面未登录可完整本地工作；登录断网可读写账号本地库并记录待同步 | 桌面 Local-first + Outbox/Inbox；见架构第 6 节 |
| Android 离线 | FR-X05：可只读查看个人缓存 | Android 必须登录且联网，不以缓存继续业务 | Android Online-only，仅保留会话令牌，不建业务库 |
| 同步 | 主要按页面打开/刷新拉取 | 登录恢复在线自动双向同步，处理版本、删除、撤权冲突 | `/sync/push`、`/sync/pull`、change log、tombstone |
| 账号 | 登录后使用 | 桌面允许未登录本地库；账号库与未登录库隔离 | 本地库按 `spaceId` 分库；未登录数据不自动合并 |
| 任务结构 | 任务 + 工作时段 | 增加任务阶段（阶段不是时间段） | `task_stage`、`task_stage_dependency` |
| 移动端 | 快速查看与轻量操作 | 增加任务番茄钟（前后台计时、70% 达标） | `focus_session`、`focus_segment` |
| AI | SRS 未定义 | 可选 AI 子用例，Key 本机保存 | 桌面 AI 客户端 + 建议确认，不进入服务端业务表 |
| 来源 | Canvas/微信/QQ 连接器 | 增加群聊筛选、AI 提取、课表导入 | 来源适配器 + 候选表 + 人工确认 |

**边界说明**：SRS 第 8 章的 Web 交互原型用于表达信息组织；实际交付是 KMP 原生客户端。UI 设计保留原型的导航与信息层级，不把网页实现当作 Android 应用已完成。

## 7 设计原则

1. **确认前不写正式数据**：候选、草案、AI 建议都只在暂存区；确认时再次校验版本与权限。
2. **共享读写在服务端复核**：桌面本地权限快照只用于交互提示，不能替代服务端鉴权。
3. **私人字段默认不返回**：工作时段、剩余估时、番茄钟片段按“仅本人”投影，共享接口不返回。
4. **一次业务动作一个事务**：完成、确认候选、接受排程、删除脱链等跨表操作由服务端或本地库单事务完成。
5. **可重试优于可避免**：所有写操作携带稳定 `operationId`；重复请求返回同一结果。
6. **时间先规则后界面**：日期精度、半开区间、Asia/Shanghai 在领域层统一实现，双端复用同一测试样本。
7. **AI 是可替换的旁路**：AI 失败不阻塞任务创建、排期和协作。

## 8 待确认事项

以下事项不阻塞设计基线，但需在第 1 周可行性验证或首次联调前确认：

| 事项 | 影响 | 当前设计假设 |
| --- | --- | --- |
| Canvas/微信/QQ 的授权方式、字段覆盖和稳定标识 | 来源连接器能否交付；是否需要降级为手动粘贴 | 先按适配器接口设计；未验证前不宣称自动检索通过 |
| 邮件验证/密码重置是否进入本期 | 账号安全流程与邮件服务依赖 | 设计保留流程；课程环境可先不做验证 |
| 生产/演示环境托管与对象存储 | 部署拓扑、备份、TLS 证书 | 单区域 Docker Compose + S3 兼容存储 |
| 附件是否做恶意文件扫描 | 上传链路与依赖 | 先做类型/大小/校验和限制，扫描可后置 |
| 桌面安装包签名方式 | Windows 安装信任与升级 | 课程环境可自签名；生产需代码签名证书 |
| AI 供应商兼容范围 | 请求/响应适配、JSON Schema 支持 | 以 OpenAI 兼容 Chat Completions 为基线，适配层隔离差异 |
| 是否允许邮件/站内提醒 | 后台任务与通知渠道 | v1 先站内提醒；邮件可选 |
