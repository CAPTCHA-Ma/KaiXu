# Windows 桌面标题栏与导航

## 范围与结构

仅实现 Windows 的 JBR 自定义标题栏，复用现有任务、日程、工作区、记录和设置页面。不引入 Jewel，不升级数据库，不实现 Linux 窗口适配。

```text
Main → KaiXuWindow（真实窗口、JBR 生命周期）
          → DesktopApp（依赖与主题）
              → DesktopNavigation（统一导航、访问历史）
                  → DesktopShell
                      ├── DesktopTitleBar
                      └── 现有侧栏与 NavHost
```

`WindowsTitleBarState` 为单个窗口提供原生按钮占用宽度及鼠标区域判定，在窗口释放时解除 JBR 标题栏和监听器。`Window` 保持默认装饰模式，不设置 `undecorated=true`。Windows 上运行时检查 JBR 的 `WindowDecorations` 服务；未使用支持此服务的 JBR 时报告明确错误。非 Windows 进程仅用于编译与业务界面测试，不代表完成其他平台的窗口集成。

## 外观

顶部固定 40 dp 高；左侧依次为设置、返回、前进，按钮为 32 dp（高度 80%）、圆角 6 dp，间隔 6 dp。色板集中在 `DesktopChromeColors`：

| 名称 | 色值 | 用途 |
| --- | --- | --- |
| color0 | `#F3F3F3` | 标题栏、原生窗口按钮默认背景 |
| color1 | `#DEDEDE` | 左侧按钮默认背景、选中图标、窗口按钮悬停/按下背景 |
| color2 | `#656565` | 未选中图标、原生窗口按钮图标 |
| color3 | `#000000` | 左侧按钮选中、悬停或按下背景 |

设置页打开时齿轮按钮持续选中；普通操作按钮只在悬停或按下时显示黑色背景。没有后退/前进历史时对应按钮禁用，图标降低不透明度。右侧保留 JBR 提供的最小化、最大化/还原和关闭按钮，通过 `controls.*` 属性设色，不绘制另一套 Compose 窗口按钮。

标题栏左侧按钮区域接收 Compose 点击；空白区域将每次鼠标事件标记为原生标题栏区域，从而保留原生拖动和双击最大化。Compose 以窗口实际按钮占用宽度留出左右空位。

## 导航规则

`DesktopNavigator` 是主页面、设置和记录详情之间跳转的统一入口。左侧导航、顶部设置按钮、页面原有设置入口和详情返回按钮都使用同一份窗口访问历史：

- 后退/前进按实际访问次序移动，记录详情保存具体种类和 ID。
- 后退后进入新页面会清除前进分支；重复点击当前页面不添加历史。
- 任务页保留为稳定根条目，任务草稿和保存状态保持；工作区与日程继续使用 Navigation 的保存/恢复机制。
- 带 ID 的记录详情重新读取对应记录，不按共享路由类型恢复旧参数。详情中尚未保存的编辑弹窗不作为历史页面保留。
- 工作区内部的详情切换、页签、筛选和编辑弹窗仍属于原页面内部状态；本轮没有把这些内部操作逐一转成历史条目。后续扩展页面时应继续接入统一导航入口。
- 历史仅在当前窗口会话内存在，不写入数据库。

## 验证

2026-11-12：使用 Linux 上的 JBRSDK 21.0.9 完成桌面编译；在独立虚拟显示环境运行全部 18 项桌面测试，全部通过，覆盖设置选中状态、历史按钮禁用、任务草稿、侧栏导航、前进分支清除、不同任务详情 ID 的历史恢复、工作区筛选恢复以及原有记录编辑流程。布局截图仅检查 Compose 部分，不能验证 Windows 原生窗口按钮。

Windows 上使用完整 JBRSDK 21，通过 `:desktopApp:run` 启动后，需要实际验收：

1. 系统默认标题文字栏被扩展内容取代，没有重复的两层顶部栏；右侧只有一组原生窗口按钮。
2. 设置按钮能打开现有设置页并保持黑底浅色图标；前进后退与左侧导航联动。
3. 在空白处拖动、双击最大化/还原，在左侧按钮上点击不会拖动窗口。
4. 最小化、最大化、还原和关闭均正常；最大化按钮悬停分屏、拖动贴边和系统动画符合 Windows 设置。
5. 100%、125%、150%、200% 显示缩放，以及跨显示器移动后，按钮不重叠、标题栏高度正确、边缘可调整大小。
6. 原生按钮默认背景为 color0，悬停/按下背景为 color1；改变焦点后颜色正常。
7. 使用 `createDistributable` / `runDistributable` 验证安装包运行时，确认同样具有 JBR 窗口能力。

本轮环境无法完成上述 Windows 原生交互和 MSI/EXE 验收。

参考：[JBR API](https://github.com/JetBrains/JetBrainsRuntimeApi)、[WindowDecorations](https://jetbrains.github.io/JetBrainsRuntimeApi/jetbrains.runtime.api/com/jetbrains/WindowDecorations.html)。
